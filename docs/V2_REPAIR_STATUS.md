## 实测补修：图片完成后一直等待

用户在 Chrome 中实测发现：ChatGPT 已显示“小猪”图片，画布仍等待 216 秒。

读取该页面 DOM 后确认：图片已加载（1254×1254），但其 alt 是 `已生成图像 1`，父级为 `[data-testid="generated-image-preview"]` / `[data-testid="generated-image-gallery"]`；原识别规则要求“已生成图片/Generated image + 冒号”或旧 `imagegen` 类，因此没有识别到图片。当前页面也已改用 `[data-turn-key]`，同一轮包住用户消息和助手回复，原 `section[data-testid^="conversation-turn-"]` 规则无法识别该结构。

本次调整：

- 图片识别支持实际观察到的 gallery/preview 标记及中英文不带冒号的 alt，并排除用户参考图区域。
- 发送前同时记录旧会话轮次和当前轮次 key，按稳定 key 排除已有轮次，兼容旧 section/article 结构。
- 助手回复按当前页面的 `[data-chatgpt-agent-turn-start]` 识别，保留多图加载等待和纯文字结束判断。
- `npm run test:content` 使用独立 Chromium profile 和实际页面结构 fixture 验证；测试执行真实 `dom.ts`，不替换识图函数。它独立于纯逻辑的 `npm test`。

补修验证通过：类型检查、66 项单测、9 项 Chrome 页面回归、构建和发布校验。第 9 项执行真实 `dom.ts` 与 `executePrompt`，在本地拦截返回的安全源页面中验证“点击发送 → 新结构 Blob 图片 → 真实 fetch / FileReader / WebCrypto → 正确画布与节点的 store-image 消息 → captured 终态”；PNG 签名和 SHA-256 另由 Node 独立核对。该测试的后台消息接收是替身，不等同于重新在用户账号发送了一次真实生图请求。

这次没有重新发送用户的提示词或消耗额外生图次数。更新本地 `dist` 后，Chrome 中需重新加载扩展并刷新 ChatGPT 页面，已打开的旧内容脚本才会被替换。

仍需留意：虚拟列表中基线时未挂载的旧历史轮次，在生成期间滚动重新挂载后不在已记录的 key 集合里；本次修复覆盖当前已挂载的旧图排除和新轮次识别，没有宣称解决全部历史懒加载场景。

## 实测补修：思考与草图阶段被当成纯文字结束

用户再次实测发现：ChatGPT 仍显示“正在勾勒草图”和 37% 进度，画布却已经提示“返回了文字，没有生成图片”。原因是旧条件把“没有匹配到停止按钮”当作完成：新助手轮次出现后，即使仍在思考或绘图，只要还没有可识别的图片，就会启动 10 秒纯文字倒计时。

这次增加正向完成判断：新版页面必须明确出现 `data-talvt-turn-state="complete"`；旧版页面需存在可见的最终回复操作。未完成轮次、可见进度条、`aria-busy` 或“正在勾勒草图”等生成阶段都会保持等待。只有确认完成、没有生图占位后，才开始 10 秒纯文字确认。已有候选图片时也会等当前轮次与生成进度结束，保留多图与取消逻辑。

新增确定性单测先复现了原错误在 11001ms 提前发生，再覆盖“25 秒后出图”“明确完成后才开始纯文字宽限”“完成状态未知继续等至超时”。

本次验证通过：69 项单测、13 项 Chrome 页面回归、类型检查、构建与发布校验。新增真实浏览器流程在没有停止按钮、轮次已标 complete 但仍有思考文字与 37% 草图进度的情况下等待 12 秒；11.5 秒检查时任务仍在运行且没有失败，图片出现后才读入真实 Blob 并发出 `captured`。`dist` 已更新；仍需在 Chrome 扩展页重新加载 Branchboard，再刷新 ChatGPT 才能替换已注入的旧脚本。
